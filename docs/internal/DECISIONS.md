## Pinned algorithms (public stability guarantees)

These are wire-format contracts (SPEC rule #3). Changing any of them is a
breaking change to persisted data, guarded by golden vectors in tests.

- **Quantity wire form**: `{"raw": "<decimal int string>", "decimals": <int>, "numeric": "<exact decimal string>", "float": <lossy float>}`. `raw` is a JSON **string**. `numeric` never uses scientific notation.
- **Asset id**: `"ast_" + sha256("\n".join(sorted(deduplicated(canonical_caip19s)))).hexdigest()[:16]`. The hash runs over the sorted, deduplicated canonical CAIP-19 set; empty input is rejected. Canonical CAIP-19 lowercases EVM addresses; Solana references keep base58 case.
- **Transaction id**: `"txn_" + sha256(f"{chain_id}|{tx_hash}|{account_id}").hexdigest()[:16]` (SPEC §4.4: hash over chain, tx hash, account).
- **Cursor token**: opaque to callers; internally a backend-monotonic last-modified sequence serialised as `f"{seq:020d}"` so lexicographic order equals numeric order.
- **JWT wire form** (tenancy): header exactly `{"alg":"HS256","typ":"JWT"}`; each segment is base64url **without padding** over `json.dumps(obj, separators=(",", ":"), sort_keys=True).encode("utf-8")`; signature = HMAC-SHA256(`secret.encode("utf-8")`, `header_b64 + "." + payload_b64`); claims are exactly `{exp, external_user_id, iat, jti, project_id, scopes}`; `iat`/`exp` are **ms-epoch ints** (deliberate deviation from RFC 7519 NumericDate seconds, SPEC §4.4 "ms epoch, everywhere, always"; these tokens are consumed by our own verify path); `scopes` is a sorted de-duplicated list; `exp` is exclusive (`now_ms >= exp` is expired). Rejection order: malformed → bad signature → expired → revoked, signature before expiry.
- **API key format**: plaintext `f"adk_{env}_{body}"`, env ∈ {`live`,`test`} (both 4 chars), body = 48 lowercase hex chars (`secrets.token_hex(24)`), total length 57; stored prefix = `plaintext[:17]`; at rest only `sha256(plaintext.encode()).hexdigest()`; compare via `hmac.compare_digest`; plaintext returned exactly once at issue/rotate.
- **Deterministic tenancy ids**: `end_user_id = "usr_" + sha256(f"{project_id}|{external_user_id}")[:16]`; `connection_id = "conn_" + sha256(f"{project_id}|{end_user_id}|{kind}|{normalized_descriptor}")[:16]`; descriptor normalization = strip, then lowercase iff kind == address and startswith "0x". Random ids: `org_`/`proj_`/`key_` + `token_hex(8)`, jti = `token_hex(16)`, project `signing_secret` = `token_hex(32)` (the per-project isolation root).
- **Embed id derivation** (0.1.1): the library's tenant id is `"usr_" + sha256(f"{project_id}|{external_user_id}")[:16]` with `project_id` taken from `Settings.project_id`, default `"embed"`: a host running the library and the HTTP API over one ledger sets its real project id so `GET /crypto/sync` reads what the library wrote (RELEASE_0.1.1 §5 #19). An embed connection id is **chain-scoped**: `"conn_" + sha256(f"embed|{tenant_id}|address|{chain_id}|{normalized_descriptor}")[:16]`, deliberately no longer byte-equal to `tenancy.connection_id`, without the chain segment one address could be watched on exactly one chain and two chains would share one sync cursor (§5 #26). `tenancy.connection_id` stays chainless: rehashing it would orphan every id the HTTP surface has already persisted. Consequence, accepted, and wider than the connection id alone: 0.1.0 embed connection ids are **not portable** to 0.1.1 (they re-derive on the next connect), and because that id IS the ledger `account_id` that `ledger.models.transaction_id` hashes (`chain_id|tx_hash|account_id`), **every transaction id of a library-ingested row re-derives with it**, including the phase-5 gate's golden vectors in `tests/contract/test_embedding.py`. Tenant ids under the default project are unchanged, so 0.1.0 rows stay addressable *by tenant*, but no longer by `account_id`: rows written by 0.1.0 keep the old chainless account id, so `facade._account_transactions` stops matching them into holdings and metrics, and re-ingesting the same history arrives as fresh rows under the new ids rather than as idempotent redeliveries. A host upgrading with library-ingested data in place either re-derives those account and transaction ids in a migration or accepts the old rows as orphaned history.
- **`grp_` is two namespaces** (0.1.1, pre-existing): `assets.groups.group_id` hashes a sorted set of asset ids (a display grouping, order-independent); `positions.models.group_id_for` hashes `adapter_id|chain_id|group_key` (a risk unit). Both mint `grp_` + 16 hex, so the two are lexically indistinguishable while being **two unrelated `grp_` namespaces**. They are **never compared**, an `AssetGroup.id` and a `PositionGroup.group_id` never meet in any call, so the divergence is registered rather than unified: changing either recipe would rehash live ids to fix a collision nobody has hit. Registered and not ignored because if something ever does try to join them, the failure will present as a lookup miss rather than a category error. Enforced by `tests/style/test_id_prefix_namespaces.py`.
- **Embed sync loop** (0.1.1): `sync()` enumerates tenants through the injected `SyncStatePort` (`tenants()`), never an in-process list, so a restarted worker resumes stored connections instead of returning a success-shaped `no_op=True` (§5 #21). `connect_address` refuses a chain absent from `ChainRegistry` (`UnknownChainError`, zero requests) rather than accepting one every later tick dies on, and one connection's `AuradefiError` is filed as `ConnectionSyncReport.failed=True`, listed in the derived `SyncReport.failed_connections`, instead of aborting the tick, spending one unit of the shared budget. A failed row is never a `no_op` (`no_op=True` means nothing needed doing, never "I could not see anything to do"), and a non-`AuradefiError` still escapes: a bug is not an API contract (§5 #24).
- **`SyncStatePort` version break** (0.1.1): growing the published Protocol from four methods to five (`tenants()`) is a BREAKING change to a structural port third parties implement, accepted deliberately: `connections(tenant_id)` requires already knowing the tenant, so with only the four methods nothing in a restarted process could ask the store what work it holds. Because the port is `runtime_checkable`, `Auradefi.__init__` isinstance-checks `sync_state` against it at BIND time, exactly as it already did for `source`'s two seams: a host store written against the 0.1.0 shape now raises `ValidationError` naming the missing method instead of binding cleanly and reporting `no_op=True` forever: the same success-shaped defect §5 #21 removes, arriving through the seam rather than inside it. `tenants()` is the one method with no `tenant_id` argument (it IS the enumeration) and yields ids only, so tenant isolation stays with the four scoped methods.
- **external_user_id invariant**: `re.fullmatch(r"[A-Za-z0-9._:-]{1,128}")`: charset excludes `@`, so email-shaped input is a ValidationError (SPEC §7.2: it is a bearer-equivalent secret and an email is guessable).
- **Audit record shape**: `{seq (per-project, from 1), event: "token.minted", project_id, external_user_id, key_id, ip, at_ms}`; append-only, no delete/update/clear.
- **Quota windows**: second = `now_ms // 1000`; day = `now_ms // 86_400_000` (UTC); month = UTC calendar `(year, month)`; `reset_at_ms` = start of the next window; a rejected hit consumes nothing.
- **TxType derivation** (decode): over `parts[]` only. Fees are siblings, structurally excluded. Empty → `interaction`; all directions `in` → `receive`; all `out` → `send`; all `self` → `self`; any mixture → `trade`. `Transaction.type` is a computed property, never a stored field (SPEC §4.4: derived, never ground truth).
- **Act id**: `f"act_{n}"`, n = zero-based position in `acts[]`. Phase 3 emits exactly one act per transaction (`act_0`); every part/fee back-references it. Multi-act decomposition (multicalls, 4337 bundles) arrives with protocol decoders.
- **decoder_version**: module constant `DECODER_VERSION = 1` in `decode/pipeline.py`, stamped identically on `Transaction.decoder_version` and `DataQuality.decoder_version` (ValidationError if they differ); bump whenever identical input would decode differently (rule #7).
- **Gas fee** (decode): `fee_wei = gas_used * gas_price_wei` from the hash's normal row, else its first tokentx row; asset = the chain's native CAIP-19; `borne_by` = `self` iff the gas row's `from` == account else `counterparty` (inbound transfers keep the fee visible but summation skips it, Vezgo's failure inverted); fees never appear in `parts[]`; failed transactions keep the fee and emit zero parts.
- **Decode timestamps**: Etherscan `timeStamp` seconds × 1000 → ms epoch; `initiated_at == confirmed_at` for mined rows.
- **Part.asset_id**: a canonical CAIP-19 string (native = `Chain.native_caip19`; ERC-20 = `f"{caip2}/erc20:{contract_lowercase}"`), never the `ast_` registry id.
- **Duplication waiver**: `decode.models.Direction` and `decode.models.transaction_id` are value-identical duplicates of `ledger.models`: the layer contract forbids decode→ledger imports. Golden vectors in `tests/ledger/test_bridge.py` pin both to the same bytes, so drift is a red test, not a debate. Same waiver: `positions.models.MetaType` duplicates `decode.models.MetaType` (positions→decode forbidden); both pin the same seven SPEC §4.3 (name, value) literals in their own test trees.
- **Position id**: `"pos_" + sha256(f"{adapter_id}|{chain_id}|{contract_lower}|{discriminator}").hexdigest()[:16]`, discriminator `""` unless sub-addressed (Uniswap V3 uses the NFT token_id decimal string). **Group id**: `"grp_" + sha256(f"{adapter_id}|{chain_id}|{group_key}").hexdigest()[:16]`, group_key = the risk-unit contract lowercase (V2 pair, V3 pool, Aave Pool). 0x addresses lowercased.
- **Position sign convention** (SPEC §4.3): an underlying's value is negative iff `meta_type == BORROWED` (unit price stays positive); `gross_assets` = exact sum of non-negative values, `total_debt` = exact sum of |negative values| (both ≥ 0), `net_worth = gross_assets - total_debt` == the naive signed sum; all Money USD.
- **Drill rounding = NONE**: value = `quantity.as_decimal() × price.amount` via context-free coefficient multiplication (sign XOR, integer coefficient product, exponents added); drill is pure: raw balances persist and re-drill against fresh prices without an RPC (SPEC §5.3).
- **Uniswap V2 pro-rata**: `underlying_raw_i = lp_raw * reserve_i_raw // total_supply_raw` (integer floor, burn semantics).
- **Uniswap V3**: sqrt ratios via the canonical TickMath integer algorithm: pinned vectors tick 0 → 79228162514264337593543950336, −887272 → 4295128739, 887272 → 1461446703485210103287273052203988822378723970342; amounts `amount0 = ((L << 96) * (sqrtB - sqrtP) // sqrtB) // sqrtP`, `amount1 = L * (sqrtP - sqrtA) // 2**96`, standard single-sided branches out of range; `in_range = tick_lower <= tick < tick_upper`; unclaimed fees = tokensOwed0/1 verbatim as CLAIMABLE underlyings.
- **Receipt-token redemption** (SPEC §4.3): `underlying_raw = share_raw * rate_raw // 10**18`, rate an 18-decimal fixed point, identity `10**18` for rebasing 1:1 receipts (stETH).
- **Aave scaling**: `health_factor = Quantity(hf_raw, 18).as_decimal()`; `ltv = Quantity(ltv_bp, 4).as_decimal()`.
- **SyntheticHolding projection** (SPEC §6.3): one holding per valued underlying; quantity = signed Decimal (negated iff BORROWED, Plaid negative-quantity extension, consistent with tax_lots `position_type: SHORT`); institution_price positive; `institution_value = exact_mul(signed_quantity, price)`; invariant: `sum(institution_value) == net_worth` exactly (Decimal).
- **secp256k1** (Bitcoin): `p = 2**256 - 2**32 - 977`; `n = 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEBAAEDCE6AF48A03BBFD25E8CD0364141`; `G = (0x79BE667EF9DCBBAC55A06295CE870B07029BFCDB2DCE28D959F2815B16F81798, 0x483ADA7726A3C4655DA4FBFC0E1108A8FD17B448A68554199C47D08FFB10D4B8)`; affine add/double, double-and-add scalar mult, inversion via `pow(x, -1, p)`; compressed parse `y = (x³+7)^((p+1)/4) mod p` with parity fix; off-curve → ValidationError.
- **Base58Check**: alphabet `123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz`; checksum = first 4 bytes of double-SHA256; each leading 0x00 byte ↔ one leading `1`.
- **bech32** (BIP173, NOT bech32m): charset `qpzry9x8gf2tvdw0s3jn54khce6mua7l`, generators `[0x3b6a57b2, 0x26508e6d, 0x1ea119fa, 0x3d4233dd, 0x2a1462b3]`, xor-constant 1, witness v0, hrp `bc`.
- **hash160** = RIPEMD160(SHA256(x)); `hashlib.new('ripemd160')` when available, else a pure-Python fallback (OpenSSL 3 CI reality) pinned to RFC vectors `'' → 9c1185a5c5e9fc54612808977ee8f548b2258d31`, `'abc' → 8eb208f7e05d987a9b044a8e98c6b087f15a0bfc`.
- **BIP32 CKDpub**: xpub version `0x0488B21E` only; deriving a hardened index (≥ 2³¹) from an xpub → ValidationError; `I_L ≥ n` or point-at-infinity child → ValidationError (deliberate deviation from BIP32's skip-to-next-index; probability < 2⁻¹²⁷, raising is honest); parent fingerprint = hash160(parent pubkey)[:4].
- **Gap-limit scan** (BIP44): default gap 20; chains scanned 0 (external) then 1 (change); derivation in batches of gap; an address is used iff `chain_stats.tx_count > 0` (mempool ignored); confirmed balance = `funded_txo_sum - spent_txo_sum`; a chain stops at gap consecutive unused (mid-batch, no further HTTP); result = used addresses only, including balance-0 swept ones, ordered (chain, index) ascending; BTC decimals = 8; caip19 = `bip122:000000000019d6689c085ae165831e93/slip44:0`.
- **Solana ScaledUiAmount detection** (sources/solana, not chains/, placement waiver: chains may import nothing): carry BOTH `Quantity(int(amount), decimals)` and `uiAmountString` verbatim; `scaled_ui = (ui_amount_string != str(Quantity(...)))`, string comparison, version-proof (jsonParsed `extensions` lists are absent on older RPCs); the `uiAmount` float is never read; display uses `ui_amount_string`, arithmetic stays on raw. Solana caip19 references keep base58 case; JSON-RPC POSTs share one cassette key, so recorded order IS the wire contract.
- **Lot id** (accounting): `"lot_" + sha256(f"{source_tx_id}|{asset_id}|{seq}").hexdigest()[:16]`, seq = zero-based ordinal among acquisitions sharing (source_tx_id, asset_id) per LotLedger lifetime.
- **Shortfall semantics** (accounting): a disposal exceeding held lots never raises; the uncovered remainder consumes a zero-cost synthetic basis, the disposal record sets `missing_basis=True` (+ flag), and the shortfall Quantity is reported. Pre-history is a data-quality fact, not an error.
- **ACB pooling**: per-asset running pool `(total_cost: exact Fraction | None, total base-unit quantity)`; acquisition adds; disposal consumes `total_cost × take_raw / pool_raw` exactly; an unpriced acquisition sets pool cost to None permanently; lots stay ground truth for open-lot reporting. The pool is a costing overlay. The two therefore DISAGREE, permanently and by design, so the report names which it costed with: `PnLReport.basis_source` is `"pool"` under ACB and `"lots"` otherwise, with `unrealized_basis` (what `unrealized` subtracted) and `open_lots_basis` (the lot sum) both exposed. Callers reach for the lot sum to check `unrealized`, which is the wrong check under ACB; naming the source is what makes that visible at the point of use rather than only in STATUS.md (#16).
- **None-propagation (PnL)**: realized = proceeds − cost_basis only when both known, else None with flags `missing_proceeds`/`missing_cost`; `report.realized` sums known disposals only and carries `missing_realized_count`; `unrealized` is None if any held asset lacks a mark or any remaining lot lacks basis.
- **Fraction→Money boundary**: exact Decimal when the reduced denominator is 2^a·5^b, else ROUND_HALF_EVEN at 28 significant digits with flag `"rounded_basis"`: all internal lot/pool arithmetic is exact rational; rounding exists only at this boundary and is always flagged.
- **Accounting event time**: `at_ms = confirmed_at if not None else initiated_at`; internal transfers (Direction.SELF entries, or tx id ∈ internal_transfer_ids) and removed transactions produce no taxable events (SPEC §9 is_internal_transfer).
- **Plaid TaxLot mapping**: institution_lot_id = lot id; original_purchase_datetime = opened_at_ms (ms int); quantity = signed Decimal; purchase_price = cost_total/quantity_original and cost_basis = remaining cost per the boundary rule; current_value = mark × remaining via context-free coefficient multiplication; position_type `LONG` (SHORT reserved).
- **Webhook signature (v1)**: header `X-Auradefi-Signature: v1=<hex>`, `<hex> = hmac.new(secret.encode("utf-8"), f"{timestamp_ms}.{body}".encode("utf-8"), hashlib.sha256).hexdigest()`, sibling header `X-Auradefi-Timestamp: str(timestamp_ms)` (ms epoch); the signed body is the exact bytes POSTed (`content=`, never `json=`); verification is `hmac.compare_digest` plus a tolerance window (default 300_000 ms, boundary inclusive) and raises plain `AuthError` for both mismatch and staleness. Golden (verified independently): secret `"0123456789abcdef"*4`, ts `1754000000000`, body `{"a":1}` → `v1=4e8c4d45b7e6229f4173bf35cc087c7162f427ab38a68f1578c99f0d60ccbd53`.
- **Webhook retry schedule**: `RETRY_SCHEDULE_MS = (0, 60_000, 300_000, 1_800_000, 7_200_000, 86_400_000)`, `MAX_ATTEMPTS = 6` (Dune SIM's 1 + 5 retries). Attempt k is due at `delivery.created_at_ms + RETRY_SCHEDULE_MS[k]`: offsets from creation, so the last attempt lands at exactly +24h ("backoff over 24h", literally) and `tick()` stays idempotent; after the sixth failure the delivery is `dead_letter` with `next_attempt_at_ms = None`. Delivery is host-scheduled: `Deliverer.tick(now_ms)` drains `pending` deliveries with `next_attempt_at_ms <= now_ms` through an injected `httpx.Client`; no threads, no sleeps; success is `200 <= status < 300`.
- **Webhook ids**: `endpoint_id = "whe_" + sha256(f"{project_id}|{url}")[:16]`; `event_id = "evt_" + sha256(f"{project_id}|{name}|{created_at_ms}|{canonical_json(data)}")[:16]`; `delivery_id = "dlv_" + sha256(f"{endpoint_id}|{event_id}|{replay_ordinal}")[:16]` (ordinal 0 original, +1 per replay); `canonical_json = json.dumps(obj, separators=(",", ":"), sort_keys=True)`; the delivery body is `canonical_json` over exactly `{created_at_ms, data, delivery_id, event_id, type}`: five keys, retry-stable (retries re-send byte-identical bodies). Event set (SPEC §7.3), exactly seven: `connection.created`, `connection.deleted`, `holdings.updated`, `transactions.available`, `sync.started`, `sync.failed`, `reorg.detected`.
- **HTTP error table** (`api/errors.py`): first hit walking `type(exc).__mro__` over ValidationError 422, CaipParseError 422, CursorError 422, ScopeError 403, TokenExpiredError 401, TokenRevokedError 401, AuthError 401, NotFoundError 404, ConflictError 409, QuotaExceededError 429, SourceError 502, AuradefiError 500; body `{"error": {"type", "message", "status", "docs_url"}}` plus `existing_id` (and `existing_connection_id` when it starts `conn_`) on 409, plus header `Retry-After` (whole seconds, ≥1) on 429. `docs_url` (0.1.2) is `f"{DOCS_URL_BASE}#{type(exc).__name__.lower()}"`, derived and never stored: the generated errors page anchors every row on its own lowercased class name, so the link is constructible and a hand-kept table of URLs cannot rot. Adopted from Plaid's error object for Plaid's reason (a `type` says what broke and nothing about what to do), and pinned against `build_site.CUSTOM_DOMAIN` in `tests/style/test_reference_is_generated.py`, because a docs link that 404s reads to a client as the type not existing. Additive to a body clients already parse by key, so a reader of the old three keys is unaffected. Non-AuradefiError exceptions are deliberately unhandled. A bug is not an API contract. CursorError is 422 rather than inheriting LedgerError's 500: a mistyped `?cursor=` is the client's fault.
- **Quota headers**: `X-RateLimit-{Limit,Remaining,Reset}-{Second,Day,Month}`. Nine headers; `Reset` is a ms-epoch int as a decimal string (§4.4 ms-everywhere), while `Retry-After` stays in seconds per RFC 9110. Emitted on every authenticated response, success or error; `GET /coverage` is unauthenticated and carries none.
- **Plaid /crypto/sync envelope**: exactly `{added, modified, removed, next_cursor, has_more}`; ADDED→added, REMOVED→removed (`{transaction_id, account_id}` only); `modified` is always a fresh `[]`. The ledger has two event kinds, a changed payload re-emits as ADDED with a bumped seq, and a reorg is REMOVED + re-ADDED (§6.4), so nothing can land there; the key exists to keep Plaid's envelope shape intact. The ledger `tenant_id` on the HTTP surface is the caller's `end_user_id` (already project-hashed).
- **Batch partial success** (§7.3): `{items, warnings}`; items same length and order as the request, each tagged `{status: "ok"|"error", chain, address}`; one quota unit per item ("billing by work done"); a request refused on its *first* item is a 429, otherwise partial success is 200. `/auth/token` responds with exactly `{"token": ...}` (§7.1: "POST → {token}. That is the whole interface").
- **Cassette recording** (0.1.2): `testing.cassettes.Recorder` wraps a real transport, appends one `{"request": {"method", "url"}, "response": {"status", "headers", "json"|"text"}}` entry per interaction, and returns to the caller the response BUILT FROM the entry it just saved, so a recording run cannot succeed where the replay of it would fail. `REDACTED_PARAMS = {"apikey", "api_key", "api-key", "access_token"}` are dropped from the recorded URL before it is written, for two reasons that both matter: a cassette is a file somebody commits, and a URL recorded WITH the key would only ever match a replay that resent the same key, so redaction is what makes the fixture keyless rather than merely safe (the bundled `sandbox.json` has the same shape because it was recorded through a keyless client). Only `content-type` survives from the response headers; cookies, tracing ids and echoed credentials are dropped because replay needs none of them. Response BODIES are stored whole and are deliberately NOT scrubbed: a service that echoes a credential back defeats redaction, and pretending otherwise would be worse than the docstring telling you to read a recording before committing it. An empty recording refuses to write, because a cassette with no interactions loads cleanly and then misses on every request, which reads as a broken library rather than as a session that recorded nothing. Replay matching is unchanged (method + host + path + sorted query), so a recorded cassette and the bundled one are one format with one matcher.
- **Duplication waiver extension**: acb.select restates FIFO's oldest-first walk and hifo/acb restate the greedy plan loop: same-wave disjoint ownership forbids the runtime import; goldens pin both.
